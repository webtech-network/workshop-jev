01 Os dois tipos de IA

O conceito que sustenta todo o resto. Guarde este primeiro.

Existem dois jeitos muito diferentes de usar um modelo de linguagem, e confundi-los é a origem de quase todo erro de projeto neste terreno.

Modo A

LLM generativo

Analogia
Um ensaísta que escreve um parecer
Devolve
Texto livre
Você pede
“Avalie esta redação”
Recebe
Três parágrafos de opinião
Trabalho extra
Você precisa extrair o número do texto

Modo B — o nosso

Modelo de decisão (Jev)

Analogia
Um avaliador com prancheta que marca X num formulário
Devolve
Um valor tipado + probabilidades
Você pede
“Numa escala de 6 níveis, qual o nível da gramática?”
Recebe
nível 2, confiança 0,62
Trabalho extra
Nenhum: o número já vem número

Tipado quer dizer que o formato da resposta é decidido antes da pergunta. Você não recebe “acho que uns 120 pontos, mas depende” — recebe um índice de 0 a 5, sempre, com a probabilidade de cada um.

O Jev é chamado de modelo System One, nome emprestado da psicologia, onde “Sistema 1” é o pensamento rápido e automático e “Sistema 2” o lento e deliberativo. O Jev é o reflexo, não a reflexão: decide em cerca de meio segundo e não escreve texto nenhum.

Consequência de projeto

O Jev é incapaz de redigir o feedback do aluno. Ele só dá notas. O parecer em texto exige um segundo modelo, generativo, alimentado pelas decisões do Jev — e essa camada ainda não existe no protótipo.

02 Mapa da arquitetura

Três zonas: o que não controlamos, o que escrevemos, o que fica em disco.

03 A unidade básica: a pergunta tipada

Tudo no Jev gira em torno disto. Três tipos, e nós usamos um só.

TipoPergunta que respondeDevolve
booleanIsto é verdade?um número de 0 a 1
choiceQual destas opções?a opção + probabilidade de cada
scoreEm que nível, numa escala?o nível + probabilidade de cada

Usamos só score, porque o ENEM é exatamente isso: cada competência vale 0, 40, 80, 120, 160 ou 200 pontos. Seis níveis.

Pegadinha de vocabulário

A documentação oficial da TypeSafe chama o tipo booleano de noul. O Vercel AI Gateway chama de boolean. São a mesma coisa com dois nomes — e se você mandar noul pelo gateway, ele recusa a requisição.

04 Anatomia da chamada

Três campos no corpo, e só três.

POST https://ai-gateway.vercel.sh/v1/evaluate
Authorization: Bearer vck_...

{
  "model": "typesafe-ai/jev",
  "state": "Título: A importância da cultura\n\nÉ notório que...",
  "questions": {
    "c1": {
      "type": "score",
      "instructions": "Avalie o domínio da escrita formal...",
      "criteria": [ 6 âncoras, em ordem do nível 0 ao 5 ]
    },
    "c2": { ... }, "c3": { ... }, "c4": { ... }, "c5": { ... }
  }
}
CampoO que éAnalogia
modelqual modelo usaro nome do avaliador que você contratou
stateo texto a ser avaliadoa prova que você põe na mesa dele
questionsas perguntas, com a régua de cada umao formulário que ele preenche

state é a palavra para gravar. Não é messages, não é prompt, não é input. É “estado”, porque o Jev pensa em termos de “avalie este estado do mundo contra estas perguntas”.

E o endpoint é /v1/evaluate, não /v1/chat/completions. Aquele recusa o modelo com a mensagem “is an evaluation model, not a language model” — uma frase que vale reconhecer, porque é o erro que você vai ver se tentar usar o Jev como se fosse um LLM comum.

As cinco competências vão numa requisição só. O Jev lê a redação uma vez e responde as cinco perguntas em paralelo. Isso importa para o custo: você paga o texto da redação uma vez, não cinco.

Como uma competência vira uma pergunta

Este é o pulo do gato. No rubric.json:

"c1": {
  "instructions": "Avalie o domínio da modalidade escrita formal...",
  "criteria": [
    "Desconhecimento total da modalidade escrita..."  ← nível 0
    "Domínio precário: desvios sistemáticos e graves..."  ← nível 1
    "Domínio insuficiente: muitos desvios..."  ← nível 2
    "Domínio mediano: majoritariamente correto, mas..."  ← nível 3
    "Bom domínio: poucos desvios..."  ← nível 4
    "Excelente domínio: desvios raros e acidentais..."  ← nível 5
  ]
}

criteria é uma lista ordenada de âncoras — cada âncora descreve o que caracteriza aquele nível. A posição na lista é o nível. O Jev nunca vê a expressão “120 pontos”: ele vê seis descrições em ordem e escolhe entre elas.

06 A pegadinha: score não é o nível escolhido

O erro que só a primeira execução real revelou.

Olhe os números da resposta acima. O nível mais provável é o 2, com 48%. Mas score veio 2,49. Por quê?

Isso se chama valor esperado: a média de todos os resultados possíveis, cada um pesado pela sua probabilidade. É como dizer que um dado “dá 3,5 em média” — 3,5 não é face nenhuma do dado, é o centro de massa das possibilidades.

Guardamos as duas leituras, e por motivos diferentes:

Campo no cacheValorPara que serve
nota_argmax80Uma nota que o ENEM aceita. É o que você mostraria a um aluno.
nota_esperada99,6Não existe no ENEM, mas preserva a indecisão — e correlaciona melhor com a nota humana.

Dizer só “nível 2” joga no lixo metade do que o modelo sabe.

Este bug nos pegou de verdade

A primeira versão do código tratava score como índice e calculava 2,49 × 40 = 99,6 chamando o resultado de nota_argmax. Só descobrimos ao fazer a primeira chamada real — nenhuma revisão de código havia pegado. É o argumento mais forte a favor de rodar cedo com --limit 1 em vez de escrever o pipeline inteiro primeiro.

08 Os quatro arquivos

Cada um com uma responsabilidade, e nenhum sabendo o que o outro faz.

rubric.json · a régua — 66 linhas, zero código

As cinco competências, cada uma com seis âncoras. É arquivo de dados, não de código. Isso é decisão de arquitetura: você reescreve a rubrica inteira, roda de novo e compara, sem nunca abrir um .py. Quem ajusta a régua — um professor — não precisa saber programar.

sample.py · escolhe quem avaliar — 99 linhas

Valida os rótulos. Confere que soma das 5 competências == nota total em cada linha; o que não bate é descartado e contado. No split de teste: 686 linhas, zero descartes.

Estratifica. O corpus é concentrado — a nota 600 aparece 91 vezes, a 680 outras 79. Sorteando 100 redações ao acaso, quase todas seriam medianas e nunca saberíamos se o Jev funciona nos extremos. Estratificar é dividir a população em faixas e pegar de cada faixa, de propósito.

aleatória:      600  600  680  600  520  680  600 ...   ← só o meio
estratificada:  0   80   160  ...  600  ...  920  1000   ← toda a faixa
Erro real, pego na primeira execução

A primeira versão desta função devolvia só notas de 0 a 440: ela percorria as faixas em ordem e parava ao atingir o total pedido, pegando sempre as mais baixas. O sintoma apareceu na própria saída do script — faixa de notas: 0 a 440 — o que é um bom argumento para scripts que imprimem o que fizeram, e não só que fizeram.

evaluate.py · conversa com o Jev — 260 linhas

O único arquivo que fala com a internet. Cinco funções encadeadas, cada uma fazendo uma coisa só e devolvendo um valor — sem efeitos escondidos.

  1. carregar_chave()de onde vem a credencial, e avisa se o ambiente divergir do arquivo
  2. montar_perguntas()rubrica → objeto questions
  3. montar_corpo()acrescenta state, que é o texto da redação
  4. chamar()HTTP com retentativas e espera crescente
  5. extrair_notas()probabilidades → nota_argmax e nota_esperada

Isso se chama função pura: dada a mesma entrada, sempre a mesma saída. A vantagem prática é que você testa extrair_notas sem internet nenhuma, passando um dicionário na mão — foi exatamente assim que o bug do score foi confirmado.

compare.py · mede a concordância — 204 linhas

Lê o cache e responde: o Jev concorda com o humano? Cinco medidas, porque nenhuma sozinha conta a história:

MedidaO que respondeOnde engana
QWKconcordância, descontando a sortedifícil de interpretar sozinho
MAEde quantos pontos ele erra, em médianão distingue errar pra cima ou pra baixo
viésele erra pra cima ou pra baixo?esconde erros que se cancelam
exata / adjacertou a faixa? errou por uma só?ignora o tamanho do erro grande
r (Pearson)ele ordena bem, mesmo errando a nota?fica alto mesmo com a nota toda deslocada

QWK (Quadratic Weighted Kappa) é a medida padrão para correção automática de redação. A ideia: 1,0 é concordância perfeita e 0,0 é o mesmo que chutar. O “quadratic” significa que errar por três faixas pesa nove vezes mais que errar por uma — errar feio é muito pior que errar de pouco.

Por que não usar só “% de acerto”? Porque a distribuição é concentrada: um modelo que responde sempre 600 acerta cerca de 13% das redações sem saber nada. Por isso o relatório sempre imprime uma baseline — se o Jev não bater o chute constante, ele não está aprendendo nada.

09 O ciclo de uma chamada

Três das proteções existem porque cada uma delas nos queimou.

ProteçãoO que evita
Para na 1ª falha de 401/403queimar 100 chamadas repetindo o mesmo erro de credencial
Para se answers vier vaziogravar cache vazio e produzir métricas silenciosamente erradas
Espera crescente no 429perder 61 de 100 chamadas quando o provedor está sobrecarregado

Espera crescente — o nome técnico é backoff exponencial. Ao receber “estou ocupado”, espera 2 s e tenta de novo; se falhar, 4 s; depois 8 s. Dobrar a espera evita que todos os clientes voltem no mesmo instante e derrubem o serviço outra vez.

10 Padrões de programação usados

Termos que aparecem em qualquer projeto sério, aqui em contexto real.

  1. PipelineCada etapa recebe a saída da anterior e não sabe nada das outras. sample.py não sabe que o Jev existe; compare.py não sabe o que é HTTP. Você troca o modelo inteiro sem tocar em dois dos três scripts.
  2. Cache-asideAntes de gastar uma chamada, veja se a resposta já está no disco. É o que permite rodar compare.py cinquenta vezes de graça enquanto se ajusta a análise.
  3. IdempotênciaRodar duas vezes dá o mesmo resultado da primeira, sem estragar nada. evaluate.py é idempotente porque pula o que já está em cache — você pode interromper no meio e rodar de novo sem medo.
  4. JSONLJSON Lines: um JSON completo por linha, em vez de um array gigante. Permite gravar incrementalmente e não perder o trabalho se travar na redação 73 — um array só é válido quando fechado; JSONL é válido a cada linha.
  5. Separação dados/lógicaA rubrica em JSON, não em Python.
  6. Fail-fastParar no primeiro sinal de problema em vez de seguir produzindo lixo. O oposto é o que mais dói: um pipeline que roda “com sucesso” e entrega números errados.

11 O que os números dizem hoje

Esta seção é a etapa 5 do workshop, e os números estão lá de propósito.

Spoiler guardado

Os resultados do Jev contra os corretores humanos — QWK por competência, viés, a baseline de chutar sempre 600 e o limiar de revisão humana — você vai medir, não ler. Rode:

python3 compare.py --cache referencia/resultados-referencia-v1.jsonl --sample sample.jsonl

e leia a saída junto com etapas/05-metricas.md. Descobrir que o modelo empilha 85 de 100 redações num nível só tem um efeito que ler a tabela pronta não tem.

Duas coisas sobre o método, que valem antes de qualquer número: a medição é zero-shot, com rubrica escrita à mão — modelos treinados no Essay-BR reportam QWK mais alto. E n=100 dá ordem de grandeza, não número final.

12 Cartão de memorização

Se você decorar só esta seção, reconstrói o resto.

LAB Jev em uma tela

JEV       avaliador com prancheta, não escritor.
          Responde perguntas TIPADAS. Não gera texto. ~0,5 s.

CHAMADA   POST /v1/evaluate          ← NÃO /v1/chat/completions
          { model, state, questions }
                      ↑
                 o TEXTO vai aqui — não em "messages"

PERGUNTA  { type: "score", instructions, criteria: [6 âncoras] }
          tipos: boolean | choice | score
          "boolean" no gateway = "noul" na doc nativa

RESPOSTA  { answers: { c1: { score, probabilities, confidence } } }
                                ↑
                     VALOR ESPERADO, não o nível!
                     2,49 com pico em 2 → média ponderada

CONVERSÃO nível (0–5) × 40 = nota (0–200) → soma 5 = total (0–1000)

PIPELINE  sample.py → sample.jsonl → evaluate.py ⇄ Gateway
          → resultados.jsonl → compare.py
           escolhe        quem          pergunta      cache    mede

REGRA     compare.py NUNCA chama a API. Só lê o cache.

13 Experimentos

Do mais seguro ao mais revelador. Nenhum custa mais que centavos.

1. Veja o valor esperado nascer

Sem chamar nada. Os dois números devem sair iguais:

python3 -c "
import json
r = json.loads(open('referencia/resultados-referencia-v1.jsonl').readline())
p = r['jev']['c1']['probabilities']
print('soma ponderada:', sum(int(k)*v for k,v in p.items()))
print('score do Jev:  ', r['jev']['c1']['score_bruto'])
"

Saem 2.49 e 2.49. Se você entendeu por quê, entendeu a seção 06.

2. Quebre a rubrica de propósito

Inverta a ordem das seis âncoras de c1 no rubric.json (o nível 0 vira o nível 5), rode com --sample sample-mini.jsonl --cache resultados-invertido.jsonl. Previsão: o QWK de c1 fica fortemente negativo. Se ficar, você entendeu que é a ordem da lista que carrega o significado.

3. Prove que o cache funciona

Rode evaluate.py --limit 10 duas vezes seguidas. Previsão: a segunda diz “pulado” dez vezes e não gasta nada.

4. Ache o limiar de revisão humana

Este é o mais consequente, porque decide se o sistema economiza trabalho ou cria mais. Rodando sobre as 500 decisões já em cache:

Limiar de confiançaDecisões abaixoFatia
0,5018 / 5004%
0,6053 / 50011%
0,70205 / 50041%

Subir o limiar de 0,60 para 0,70 salta de 11% para 41% das decisões na fila humana. Essa é a curva que decide a viabilidade do produto — e ela não tem nada a ver com o modelo, só com o quanto de erro você aceita.
